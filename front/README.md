# coach-km-app: front (Vue 3 PWA)

Mobile-first PWA where coaches log the km they drive for the association. Read [`UX.md`](./UX.md)
before working on any screen, and [`../api/API.md`](../api/API.md) for the API contract.

Stack: Vue 3 (`<script setup>`) + TypeScript (strict) + Vite, Vuetify 3 (auto-imported by
`vite-plugin-vuetify`), Pinia (+ `pinia-plugin-persistedstate`), Vue Router 4, Axios, `vite-plugin-pwa`.
Tooling: ESLint (flat config) + Prettier, Vitest + `@vue/test-utils` + jsdom, MSW.

## Setup

Requires Node 22.13+ or 24+.

```sh
cd front
npm install
npm run dev        # http://localhost:5173
```

Read the values through `src/config` (`config.apiBaseUrl`, `config.useMocks`), not `import.meta.env`.

## Mock API (dev only)

With `VITE_USE_MOCKS=true` (the default in `.env.development`), `src/main.ts` awaits `enableMocks()` from
`src/mocks` before mounting the app: an [MSW](https://mswjs.io) service worker answers every `/api/*` call
following [`api/API.md`](../api/API.md) (same paths, bodies, status codes and `{ error }` messages), so the whole
UI works without the Go API. Other requests (Vite modules, assets) go to the network untouched.

- **Dev only:** the worker is loaded through a dynamic import behind `import.meta.env.DEV`, so MSW is never in the
  production bundle. `public/mockServiceWorker.js` (generated by `npx msw init public/ --save`; re-run it after
  upgrading `msw`) is ignored by the PWA service worker (not precached, not a navigation fallback).
- **Data:** an in-memory store persisted to `localStorage` (`coach-km.mock-db.v1`), so changes survive reloads.
  To start over, run `__coachKmMocks.reset()` in the devtools console (or clear the site data).
- **Auth:** mock tokens are opaque strings `mock-token-<userId>`; `/admin/*` answers 403 to non-presidents.

## Why `/api` and the proxy

The Go API sends **no CORS headers**, and it is not changed for the front. So the browser must always call the
API on the **same origin** as the app, under the `/api` prefix, and something in front strips the prefix:

```
browser  →  /api/trips?year=2026  →  proxy  →  http://localhost:3000/trips?year=2026
```

- **Dev / preview:** Vite does it (`server.proxy` and `preview.proxy` in `vite.config.ts`).
- **Production:** the reverse proxy serving `dist/` must do the same. Example with nginx:

  ```nginx
  location /api/ {
      proxy_pass http://127.0.0.1:3000/;   # trailing slash strips the /api prefix
      proxy_set_header Host $host;
      proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
  }
  location / {
      try_files $uri $uri/ /index.html;    # SPA history fallback
  }
  ```

## PWA (service worker, install, updates)

The production build generates `dist/sw.js` and `dist/manifest.webmanifest` (`vite-plugin-pwa`, see
`vite.config.ts`). The service worker is not active in `npm run dev`; test it with `npm run build && npm run preview`.

- **App shell:** every built JS/CSS/HTML file and the icons are precached (cache-first); navigations fall back to
  `index.html`, except `/api/*` and `/mockServiceWorker.js`.
- **API GETs:** `NetworkFirst` (4 s timeout, then the cache; 80 entries, 7 days; only 200 responses) in the
  `coach-km-api` cache. Never cached: `/api/export`, `/api/receipts/*`, `/api/auth/*`, requests without a token.
  The cache key includes a hash of the `Authorization` header, so a response is only served back to the session
  that fetched it, and logout deletes the cache (`src/plugins/pwa-cache.ts`). Mutations are never cached: offline,
  they go to the trips store's queue.
- **Static files outside the precache, fonts:** `StaleWhileRevalidate` (`coach-km-assets`).
- **Updates:** a new version installs in the background and takes control; the open page switches to it on the
  next in-app navigation (a full page load), so a form being filled in is never reloaded under the user
  (`src/plugins/pwa.ts`).
- **Install:** `src/components/pwa/InstallPrompt.vue` (Android/desktop install button, iOS "Partager → Sur
  l'écran d'accueil" hint).
- **Icons:** SVG sources in `public/icons/`; run `npm run icons` after changing them and commit the PNGs.

## Source layout

```
src/
  api/          Axios client + typed endpoints (issue #7)
  types/        Types mirroring api/API.md (issue #7)
  domain/       Pure helpers: barème, formatting (issues #7, #11)
  mocks/        MSW mock API (handlers/, db.ts, seed.ts), dev only, VITE_USE_MOCKS (issue #8)
  stores/       Pinia stores (issue #9)
  router/       Routes + auth guard (issue #10)
  composables/  Reusable composition functions (issue #10)
  views/        Route-level screens, lazy loaded (issue #11)
  components/   Shared components (issue #11)
  config/       Typed runtime config from the env
  plugins/      vuetify.ts: themes, fr locale, component defaults
  styles/       settings.scss (Vuetify SASS vars), main.scss (globals)
  test/         Vitest setup
```

Conventions: import with the `@/` alias (`@/stores/auth`), tests live next to the code as `*.spec.ts`.
Vuetify themes are named `light` and `dark`; the default `system` follows `prefers-color-scheme`.
`rounded="lg"` is 12 px (cards), `rounded="xl"` is 24 px (FAB).
